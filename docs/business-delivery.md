# 中文短视频的英文交付

剪辑工作台面向中文口播、旅行介绍和产品说明视频的英文交付。
使用者上传素材、提出剪辑需求或直接载入原片字幕后，
可以完成原文校订、英文翻译、配音试听和交付下载。
项目继续基于 CamCat 的素材分析、检索、LangGraph 剪辑、版本管理和 FFmpeg 导出。

## 使用流程

1. 上传原片，建立带字幕的剪辑时间线，或在「译制」点击「载入原片与识别字幕」。
   也可以在聊天区输入「把原文字幕翻译成英文并配音」，后台将连续生成草稿版本。
2. 打开「译制」→「原文校订」，改正识别中的名字、品牌和错词，点击「保存字幕修改」。
   若出现「原始识别有 N 处建议复核」，可展开查看原片名称、时间段和低置信词。
3. 选择英文，在术语表按每行 `原词 = 译词` 填写约定用词。点击「翻译字幕」，
   核对生成结果后「确认并写入时间线」。术语表随这次翻译保存到项目版本，重开项目可以复用。
4. 在「译文校订」中修改文字和时间，保存后生成配音。逐句试听后应用配音。
   当前配置提供一个英文音色；其他语言可以翻译字幕，匹配音色后才能配音。
   每句按真实音频测量，最高 1.2 倍速，用户勾选后才允许一次时长改写。
5. 在交付区点击「已校对字幕并试听，确认交付审校」。确认会产生一个带时间及操作者记录的新版本。
6. 点击「生成交付视频」，完成后可播放成片并「下载交付包」。

原片及会话沿用四小时临时保留，界面显示保留截止时间；请在截止前下载交付文件。
当前部署使用本地单人工作台模式，适合创作者或运营人员独立操作。

## 交付文件

一个 ZIP 对应一个已确认的项目版本，包含：

| 文件 | 接收方用途 |
| --- | --- |
| `video.mp4` | 实际导出的配音成片 |
| `source.srt` | 已校订原文字幕 |
| `translation.srt` | 英文字幕，可用于支持外挂字幕的平台 |
| `bilingual.srt` | 原文与译文对照字幕 |
| `glossary.csv` | 本次项目使用的术语表，UTF-8 BOM |
| `delivery.json` | 剪辑名称、交付编号、版本、语言、审校时间及文件清单 |

视频来自该版本的成功渲染任务，须通过完整解码验证，打包时再次核对 SHA256。
交付清单使用业务信息；对象存储地址、私有路径、模型服务凭证留在服务端。
ZIP 使用 Python 标准库，下载使用 Starlette 文件响应；打包工作目录位于数据盘，
响应结束或连接异常后清理。默认最大交付视频为 512 MiB，通过 `CAMCAT_DELIVERY_MAX_BYTES` 配置。

## 修改与失败处理

| 情况 | 界面及操作 |
| --- | --- |
| 原文或原文时间改变 | 提示重新翻译；配音、交付入口要求使用新的翻译 |
| 译文或译文时间改变 | 提示重新配音；旧配音无法直接导出 |
| 审校后的版本改变 | 重新确认审校，再导出该版本 |
| 并发版本冲突 | 返回 409，保留字幕草稿，刷新后重新检查 |
| 配音超出时间窗 | 缩短译文或明确允许一次改写；新文本仍需试听确认 |
| 渲染失败 | 显示失败信息，可重新生成交付视频 |
| 原片会话过期 | 返回 410，请重新上传 |

普通剪辑预览仍使用 CamCat 原有导出入口；交付包使用绑定版本的审校与渲染记录。

## 本轮验收及证据

单元检查覆盖原文变更失效、审校版本绑定、字幕与视频一致性、识别提示和下载异常清理。
真实 API 验收调用本地模型、Piper、PostgreSQL、队列、MinIO 和 FFmpeg，
覆盖术语保存、显式确认、重复确认、跨会话隔离、交付包校验和修改后失效。
浏览器验收操作实际界面，验证原文编辑、重开项目恢复术语、配音、审校、播放及 ZIP 下载。
测试使用已真实分析的许可口播素材，源字幕修正为验收作者输入，翻译与配音由真实服务生成。

结果位于 `/data/zjr/camcat_studio/checks/business_delivery/`；
日志位于 `/data/zjr/camcat_studio/logs/business-delivery-*`。
原有模型质量基线和固定公开样本结果见[译制质量记录](localization-quality-20261115.md)。

2026-11-15 的实际结果：后端 536 项、前端 34 项单元测试通过，
Ruff、mypy 112 文件、OpenAPI 契约检查和前端构建通过。
真实 API 交付测试通过（18.83 秒），新增业务浏览器旅程通过（33.58 秒），
原有完整浏览器旅程通过（220.34 秒），均无跳过。
原流程素材实测约 5.06 秒，原验收目标为 4 秒。首次使用 12 秒目标出现约束失败，
按原验收的 4 秒配置复测后通过，首次失败记录保留。
本地单人模式忽略客户端身份头，跨资源验证使用不同会话，返回 404。

完整交付包示例为 `demos/business_delivery/customer-delivery.zip`，
对应的 `video.mp4`、三份字幕、术语表与 `delivery.json` 也单独保存，路径相对项目数据盘。
自动化验收执行了审校按钮的交互，人工语义及听感评审仍由实际操作者完成。
最终版本与证据收据为 `checks/business_delivery/acceptance-v1.json`，
当前业务版指针为 `config/active-delivery.json`。核对了 176 项宿主生产源码，
其中 170 项与运行容器一致，前端入口及两个实际资源文件也与相同参数的构建产物一致。

## 后续业务指标

后续试用按工作单统计交付成功率、第一次审校通过率、人工修改句数、
从提交到下载的用时及失败后的恢复时间。人工审校时间与模型、排队、渲染时间分别记录。
当前真实任务已有创建、开始、完成时间和版本审计，可以用于还原技术处理耗时。
团队账号审批、跨项目品牌词库和批量视频工作单作为下一轮功能。
